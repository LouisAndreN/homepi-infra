# MQTT device ACL (allow-list from the registry)

## Model

- Listener 8883 (devices, mTLS, `use_identity_as_username`): ACL
  `/etc/mosquitto/acl/devices.acl`, generated by `homepi-acl-sync` from
  `/var/lib/homepi/devices.db`. Only devices with status `active`, `approved`
  or `pre_announced` and a CN matching `^esp32-[0-9a-f]{8}$` get their four
  topics (write `iot/<id>/sensors`, `nilm`, `status`; read `iot/<id>/commands`).
  Every other certificate has no rule and is denied: unknown CN, suspended
  device, non-device names such as `homepi.internal`, and the service account
  names `homepi-api` and `telegraf-bridge`.
- Listener 1883 (loopback, password file): static `services.acl` for
  `telegraf-bridge` and `homepi-api`, deployed and pinned by the `pki` role.
- `homepi-acl-sync` runs every 60 s (timer), reads the registry as
  `homepi-api` (WAL database), writes atomically and reloads mosquitto
  (SIGHUP) only when the content changes. It refuses to empty the list in one
  run. Metrics: `homepi_mqtt_acl_*` in the node_exporter textfile directory;
  alerts `MqttAclSyncFailing` and `MqttAclSyncStale`.

## Revoke a device

Set its status to anything outside the allowed list (the API `suspend`
endpoint sets `suspended`), then wait up to about 70 s or run
`systemctl start homepi-acl-sync`. Also `step ca revoke` its certificate so it
cannot renew.

## Limits

- An open connection is not dropped: after a reload it can no longer publish
  or receive, but it stays connected until it reconnects.
- The ACL keys on the certificate CN only. Any valid certificate with an
  allowed device's CN works until it expires: shorter certificates are the
  remaining mitigation.
- Before this change, the 8883 listener shared the services ACL and used
  `pattern` rules: any certificate of the CA could publish telemetry under its
  own CN (proven 2026-11-08 with a test certificate `acltest.homepi.internal`),
  and a certificate named `homepi-api` or `telegraf-bridge` would have had the
  service rights.

## Proof (v0.1.73, 2026-11-08)

- Before: a test certificate `acltest.homepi.internal` (admin provisioner,
  10 min) published on `iot/acltest.homepi.internal/sensors` and the message
  reached the subscribers.
- After the cutover: the 7 devices reconnected and the 5 sensor devices of the
  baseline published again; the same kind of test certificate was denied;
  `esp32-0a171a18` set to `suspended` stopped publishing while the others
  continued, and published again once set back to `active`; Telegraf showed no
  authorization error. Backups of the previous files:
  `/var/backups/mosquitto/*.before-acl`.
