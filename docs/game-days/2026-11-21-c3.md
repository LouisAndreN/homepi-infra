## Context

C3 is the first full drill: the production NVMe (Micron 2200) is physically removed, and the whole
platform is rebuilt on a spare (Samsung 990 PRO) from the signed GitHub repository and the
age-encrypted archives in S3 only. Public write-up: article 20 of the series.

## Incidents during the drill

- **pironman5 vendor installer.** Run pinned and hashed, but its cloned repository ran
  `install_influxdb.sh`, which uninstalled `influxdb2` (13 min outage, data intact on its volume),
  created a `pironman5` user with `NOPASSWD: /usr/bin/systemctl` and made `/opt/pironman5` 775.
  Reverted by hand. The runbook no longer tells anyone to run it.
- **R8, production unreachable for a night.** The production disk came back on another DHCP address.
  sshd (`ListenAddress` pinned by hand) and Unbound (bound to one address, no `ip-freebind`) depended on
  the old one: no SSH from the LAN, no DNS at all, so no off-site upload and no heartbeat. Without SSH
  and without pironman5 there was no clean shutdown: power was cut twice. Fixed by a router
  reservation that night, then for good in v0.1.134.

## Lessons

1. "The configuration is in Git" is not true until a first install proves it: adopting a running host
   checks what exists, a rebuild creates it from nothing (14 defects).
2. A checker must prove writes, not reads: Authelia and the API were green while every write failed.
3. Hand-made production changes vanish silently on a rebuild.
4. Invisible dependencies bite on the way back: an unreserved address held SSH, DNS and the house.
5. A supply chain is trusted only as far as it was read.
6. The core held: devices came back with their identities, no certificate warning, GitOps converged on
   both sides, the dead man's switch fired in 13 minutes.
